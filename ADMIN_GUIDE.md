# Администрирование «Русского следа» — первый этап CMS

Реализованы серверное хранилище, миграция существующего словаря и административный редактор слов. Это **не законченная CMS из полного ТЗ**: визуальный журнал, редактирование главной, медиатека и редактор библиографических источников ещё не реализованы. Существующие три публикации журнала остаются в `src/data/journal.ts`, доступны на сайте и не потеряны, но пока не редактируются через панель.

## Установка и запуск

Нужны Node.js **24.22+** (встроенный SQLite) и npm. Из корня репозитория:

```sh
npm ci
npm run server
```

Первый запуск создаёт `.cms/content.sqlite`, переносит все 58 текущих записей со всеми наблюдениями, ссылками, страницами и статусами. Миграция отмечается в таблице `migrations`; повторный запуск не перезаписывает правки. `research/` и исходный `src/data/catalog.json` не изменяются. Миграция копирует уже существующий каталог приложения; новый импорт или научная перепроверка PDF не выполнялись.

Во втором терминале:

```sh
npm run dev -- --port 5173 --strictPort
```

Откройте `/admin` на том же адресе `http://localhost:5173`, который указан в `CMS_ORIGIN` (по умолчанию именно этот адрес). Для использования `127.0.0.1` вместо `localhost` явно задайте `CMS_ORIGIN=http://127.0.0.1:5173` серверу. Vite направляет `/api` на сервер порта 3001. Живые процессы после восстановления облачной среды нужно запускать заново.

## Первоначальное создание владельца

Публичной регистрации и стандартного пароля нет. На доверенном сервере, в Bash:

```sh
read -r -s -p 'Новый пароль владельца (не менее 14 символов): ' CMS_OWNER_PASSWORD
export CMS_OWNER_PASSWORD
npm run admin:create
unset CMS_OWNER_PASSWORD
```

Пароль вводится скрыто и не записывается командой в историю shell. Выбирайте уникальный случайный пароль из менеджера паролей. Не сохраняйте пароль в Git, `.env`, скриншотах или сообщениях. В БД остаётся только scrypt-хеш со случайной солью. Повторное создание владельца запрещено; автоматического сброса через сайт нет. Реальный владелец в рамках разработки не создавался.

При нестандартном пути одинаковый `CMS_DB_PATH` должен быть задан для сервера, создания владельца, копирования и восстановления. Эта переменная содержит путь, а не пароль. Рекомендуется постоянный абсолютный путь на защищённом диске.

## Вход, словарь и публикация

1. Откройте `/admin`, введите пароль. Сессия действует 8 часов. После пяти неудачных попыток адрес блокируется на 15 минут. Кнопка «Выйти» отзывает серверную сессию.
2. Сразу доступны все 58 существующих слов. Найдите нужную запись по русскому слову, URL или иностранной форме; можно фильтровать по редакционному статусу.
3. Редактируйте поля, добавляйте элементы списков, языки, наблюдения и ссылки. ID и URL существующих записей неизменяемы, чтобы сохранить ссылки. «Новое слово» создаёт пустую запись; заполните слово и URL латиницей с дефисами.
4. Свободные исследовательские поля допускают пробелы в данных. Значения, примеры и частотности вводите только с атрибуцией. Источники выбираются из существующего библиографического реестра; добавление и проверка новых источников в этом этапе не поддержаны.
5. «Предпросмотр» показывает статью существующим публичным компонентом без публикации. Затем вернитесь к редактору.
6. Выберите **редакционный** статус: «Черновик», «На проверке», «Опубликовано», «Архивировано», затем сохраните. Публикация требует подтверждения. Черновики новых слов не видны на сайте. Черновик ранее опубликованной записи сохраняет прежнюю публичную версию до новой публикации.
7. Для снятия статьи с сайта сохраните статус «Архивировано». Для восстановления выберите нужный статус и сохраните. История позволяет загрузить старую ревизию в черновик; сохранение создаст новую ревизию. Старая история не удаляется.
8. После публикации обновите страницу публичного сайта: словарь, поиск, сравнение и карта читают один серверный опубликованный каталог. Новая вкладка получает свежие данные; автоматической синхронизации уже открытых вкладок нет. Полностью пустой опубликованный словарь поддержан.

**Научные статусы независимы от редакционных.** Научный статус никогда не повышается при публикации автоматически. Действующий `publicationStatus` сохранён как прежний научный допуск к карте/слову дня; это не новый редакционный статус. Научно подтверждённая форма требует источника с `verifiedAt`; подтверждённое утверждение — ссылку на проверенный источник. Карта и слово дня по-прежнему исключают демозаписи и непроверенные формы. В текущем каталоге источники не верифицированы заново: его материалы нельзя автоматически сделать подтверждёнными. Для текущих трёх языков допускаются страны US, FR и AM соответственно.

Поля произношения, регистра, частотности, значений, примеров и степени освоения сохраняются и отображаются на статье. Графика, фонетика, семантика, грамматика, хронология, библиография и открытые вопросы представлены типизированными исследовательскими наблюдениями с независимыми статусами и ссылками. Их можно добавлять через «Исследовательские наблюдения».

## Резервная копия и восстановление

Копии содержат парольный хеш, сессии и непубличные черновики. Держите их вне Git и web-каталога с ограниченными правами; резервируйте на отдельный носитель. Наличие локальной команды само по себе не означает автоматического резервирования.

Согласованная SQLite-копия (можно при работающем сервере):

```sh
npm run db:backup -- /защищённый/существующий-каталог/cms-backup.sqlite
```

Команда не перезаписывает имеющийся файл и выставляет права 0600. Копирование только основного файла БД работающего WAL-сервера обычным `cp` небезопасно.

Для восстановления остановите сервер. Сохраните резервную копию текущей БД указанной выше командой. Скопируйте нужную резервную копию **в новый файл**, а не поверх работающей БД, например `.cms/restored.sqlite`. Установите права 0600 и проверьте её:

```sh
CMS_DB_PATH="$PWD/.cms/restored.sqlite" node --input-type=module -e 'import {DatabaseSync} from "node:sqlite"; const db=new DatabaseSync(process.env.CMS_DB_PATH); console.log(db.prepare("PRAGMA integrity_check").all()); db.exec("DELETE FROM sessions; DELETE FROM attempts"); db.close();'
CMS_DB_PATH="$PWD/.cms/restored.sqlite" npm run server
```

Продолжайте только при результате `ok`. Проверка отзывает все восстановленные сессии; войдите заново. Зафиксируйте новый `CMS_DB_PATH` в конфигурации процесса. Не удаляйте прежнюю БД, пока не проверили словарь и историю.

## Односерверный запуск

```sh
npm run build
NODE_ENV=production CMS_ORIGIN=https://ваш-домен.example npm run server
```

Сервер обслуживает собранный сайт и API на loopback. Нужны HTTPS reverse proxy и постоянный диск для БД; serverless-хостинг с временной файловой системой не подходит. Публичное размещение здесь не выполнялось. В production cookies получают `Secure`, `HttpOnly`, `SameSite=Strict` и префикс `__Host-`; origin проверяется на всех изменяющих запросах, включая вход. Прокси должен сохранять Host. По умолчанию все запросы через один reverse proxy делят лимит входа: `X-Forwarded-For` намеренно не считается доверенным. Для UI доступны только опубликованные данные, административные API всегда проверяют серверную сессию.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:server
npm run build
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

`test:e2e` создаёт временную БД и случайный пароль, запускает API и проверяет публичный сайт и CMS. Не запускайте одновременно реальный сервер порта 3001. Тестовые учётные данные не используются в рабочей БД. На машине без системного Chromium установите браузер Playwright и опустите override.

## Следующие этапы

- Журнал: миграция всех трёх публикаций, визуальное форматирование, связи, порядок, даты и обложки.
- Главная: перенос жёстко заданных текстов, подписей и подборок в редактор; ручное слово дня с научными ограничениями.
- Источники: безопасное редактирование и документированная процедура научной проверки.
- Медиа: проверка байтов и размеров изображений, библиотека, alt, контроль использования и удаление с подтверждением.
- Расширение миграций и сквозных тестов на эти компоненты, настройка автоматических внешних копий.
