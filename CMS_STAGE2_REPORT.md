# Результат второго этапа CMS — 15.11.2026

Ветка `feat/cms-stage2` создана от `release/cms-stage1-macbook`. Архитектура React/Vite + Node.js API + SQLite и авторизация единственного владельца сохранены. Первый этап остаётся доступен в прежней ветке. Пользовательская база на MacBook недоступна этому сеансу; тесты обновления выполнялись на отдельной базе со схемой первого этапа, владельцем, сессией, 58 записями, личной Unicode-правкой и историей.

## Выполнено

2А: предварительная согласованная резервная копия и транзакционная повторяемая миграция; категории и их связи с черновиком/публичным снимком, переименование/объединение/удаление с проверкой связей; улучшенный редактор, дублирование, пакетные операции и корзина. UUID убраны из основной формы. Изменение категории повышает версии затронутых статей, защищая от устаревших редакторов. Черновики и научные статусы не публикуются автоматически при массовом назначении категории.

2Б: перенос трёх существующих статей журнала с исходными URL и содержанием в отдельные записи SQLite, редактор Markdown с безопасным предпросмотром, создание/дублирование/публикация/планирование/архив/корзина. Отдельная модель выпуска «Слово дня», связанные слова и источники, заполнение из имеющихся сведений без генерации фактов, календарь, архив и постоянные адреса по URL выпуска, соседние выпуски, последний выпуск при отсутствии сегодняшнего. Время задаётся в часовом поясе проекта и сохраняется как абсолютный момент; начало дня рассчитывается по настройке проекта. Две активные записи на одну дату запрещены, несколько черновиков допустимы.

2В: справочник источников в SQLite и выбор/создание из редакторов; серверная проверка научных ссылок; медиатека PNG/JPEG/WebP с декодированием, ограничениями размера/пикселей и перекодированием в WebP; метаданные изображения и повторное использование. Изображения хранятся BLOB в SQLite и резервируются вместе с базой. Единая история новых операций и сохранённая история этапа 1; сравнение снимков и восстановление в черновик. Сравнение открывает тот же редактор языковой карточки, не хранит отдельную копию научных полей. Скрытые языковые карточки не покидают публичный API. Основной набор и порядок восьми слов сохранены; справочник языков можно расширять через настройки.

Все изменяющие API проверяют действующую серверную сессию и Origin; данные валидируются сервером, связанные изменения выполняются в транзакциях. Ссылка на источник, привязка слова и использование картинки проверяются перед удалением; связанные научные материалы автоматически не удаляются. Старые идентификаторы, URL, владелец и авторизация не сбрасываются. `db:backup` больше не вызывает миграцию: открывает существующую базу только для чтения. Для явного обновления добавлена команда `npm run db:migrate`.

## Проверки

На рабочем дереве и при чистой установке из коммитов прошли: TypeScript, ESLint, production-сборка; **16 unit-тестов**, **5 серверных тестов**, **10 браузерных сценариев Chromium**. В серверных тестах проверены чистая база и обновление схемы этапа 1, резервная копия до миграции, сохранение владельца/сессии/Unicode-правок/истории, повторное открытие, категории, откат целой пакетной операции при конфликте, дублирование/корзина, публикация снимков, даты и часовой пояс, источники, запрет SVG и нормализация изображения, запреты неавторизованным запросам и восстановление истории. Unit-тест времени проверяет также несуществующее местное время при переходе DST.

Браузерные сценарии проверяют прежние словарь/поиск/карту/мобильную навигацию и CMS, категории и дублирование, сохранение после перезагрузки, Markdown без исполнения script, медиатеку и обложку, старые статьи журнала, архивы ежедневных выпусков, скрытие будущего выпуска, связь сравнения со словарём, скрытие карточки и историю. Тесты используют отдельную временную базу и случайного тестового владельца. Данные рабочей базы не меняются ими.

Дополнительно на чистой установке выполнены два последовательных `npm run db:migrate`: 58 записей сохранены. Отдельно проверено, что новая команда db:backup копирует базу со схемой этапа 1, не применяя к оригиналу или копии миграцию 2. Рабочая база облачной машины обновлена после отдельной копии; база MacBook не открывалась.

Аудит npm: до исправления — 2 critical и 8 moderate по графу; после адресного обновления Vitest до 4.1.12 — 0 critical/high и 7 moderate в dev-цепочке линтера. Для `npm audit --omit=dev` — 0 находок. Подробности: SECURITY_DEPENDENCIES.md. Не применялись force-обновление или небезопасные overrides.

## Ограничения и действия владельца

Выполнить обновление на MacBook и проверку в настоящем Safari должен владелец по CMS_STAGE2_UPDATE.md. Требуются остановка обоих процессов, личная копия текущей базы до переключения ветки, npm ci, db:migrate, build и запуск API/Vite; вход прежним паролем. Автоматический сценарий Linux не является проверкой Safari или вашей конкретной базы. Публичное размещение не выполнялось.

История показывает два JSON-снимка рядом, не построчный diff. Markdown поддерживает таблицы, ссылки, изображения и абзацы-примечания; специализированного автоматического библиографического форматирования и WYSIWYG нет. Справочник категорий связан со словарём; категории журнала — самостоятельные текстовые метки. Изображения по прямым URL публичны. Планирование рассчитывается при запросе к API; push-уведомлений/обновления открытой страницы ровно в полночь нет. Поля примеров и адаптации сохраняют текст с атрибуцией, но не создают новые научные подтверждения сами по себе. Не добавлялись универсальный конструктор главной, импорт PDF/XLSX, публичные серверные формы или новый механизм рисования карты.

Перенос старого журнала — перенос уже существующих редакционных заметок, не импорт новых словарных фактов. `research/`, исходный каталог и PDF не изменялись; новый научный аудит досье не заявляется. Сквозные тесты, документация и SQL-миграция входят в ветку; базы, пароли, сессии, резервные копии и зависимости node_modules в Git не входят.
