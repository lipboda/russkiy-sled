# Третий этап: безопасное обновление MacBook

Ветка **feat/cms-stage3-editor** создана от **feat/cms-stage2**. Архитектура и прежняя учётная запись сохранены. База вашего MacBook в облачной среде недоступна: её содержимое здесь не удалялось и не проверялось.

## Обновление

1. В двух окнах Терминала остановите API и Vite нажатием **Control+C**.
2. В корне проекта, ещё на прежней ветке, создайте копию:

```sh
mkdir -p -m 700 "$HOME/russkiy-sled-backups"
npm run db:backup -- "$HOME/russkiy-sled-backups/before-stage3.sqlite"
```

Если имя уже занято, выберите другое. При нестандартном CMS_DB_PATH укажите тот же путь, который использует API. Сохраните копию также на другом носителе. Не копируйте отдельно работающий content.sqlite через cp.

3. В GitHub Desktop сохраните свои незакоммиченные изменения кода. Не выбирайте Discard Changes. Нажмите **Fetch origin → Current Branch → feat/cms-stage3-editor**, затем Pull origin при необходимости. `.cms/` остаётся на компьютере, поскольку не входит в Git.
4. Откройте **Repository → Open in Terminal** и выполните:

```sh
node --version
npm --version
npm ci
npm run db:migrate
npm run build
```

В облачной Linux-среде проверены Node.js **24.22.1** и **26.13.0**, npm **11.9.0**. Ваш Node.js 26.13.0 не требуется переустанавливать только из-за рекомендации предыдущей документации. `.nvmrc` оставлена на 24.22.1 как проверенная альтернативная версия для пользователей nvm. Более старые версии, другие Node 26.x и настоящий macOS/Safari здесь не проверялись. Не используйте audit fix --force.

Миграция 3 перед изменением схемы автоматически сохраняет согласованную копию SQLite в `backups/` рядом с файлом базы, обычно `.cms/backups/before-stage3-….sqlite`. Если копию создать нельзя, миграция не продолжается. Добавляются необязательные метаданные языков; словарь и публикации не переимпортируются, владелец и его пароль не сбрасываются. Повторная миграция безопасна. На чистой установке последовательно выполняются миграции 1–3; существующая база не заменяется исходным каталогом.

5. Запустите API:

```sh
npm run server
```

Во втором терминале из той же папки:

```sh
npm run dev -- --port 5173 --strictPort
```

6. В Safari откройте **http://localhost:5173/admin** и войдите **прежним паролем**. Создавать владельца заново не нужно. Сайт: **http://localhost:5173/**. Не заменяйте localhost на другой хост без согласования CMS_ORIGIN.

## Краткая карточка, темы, ссылки и языки

В словаре нажмите «Новое слово» и выберите «Краткая карточка». Для публикации достаточно русского слова и содержательного краткого определения. Ударение, часть речи, темы, изображение и иностранные формы необязательны. URL создаётся автоматически; дополнительные настройки позволяют его изменить до первого сохранения.

В «Темах слова» введите новое название в «Добавить тему…», нажмите Enter или «Создать тему». Тема сохранится в справочнике и назначится редактируемой статье. Статья от этого не публикуется. При совпадении нормализованного названия используется существующая тема. Можно назначить несколько тем и убрать тег, не удаляя категорию. После публикации тема появится в публичном фильтре для связанных опубликованных слов.

В разделе «Источники статьи» нажмите «Добавить ещё ссылку» и вставьте HTTP/HTTPS URL. Название и комментарий необязательны. Ссылка сохраняется со статьёй; библиотека повторно использует источник с таким URL. Название/комментарий этой ссылки относятся к данной связи и не перезаписывают описание источника в других статьях. Удаление связи не удаляет источник. Прежние библиографические источники без URL сохраняются. Добавленная ссылка не повышает научную достоверность.

В «Языковых карточках» нажмите «Добавить язык». Выберите существующий или «Создать новый язык». Обязательно только название: код, регион, родное название и разновидность необязательны. При отсутствии международного кода система создаёт внутренний ID и не выдаёт его за официальный код. Пока новый язык сохраняется, прежняя карточка блокируется для ввода, чтобы случайно не изменить её вместо новой.

Заполните иностранную форму, описание и **тип соответствия**: перевод, культурное соответствие, вероятное заимствование и т. д. Тип и достоверность формы независимы. По кнопке «Расширить описание» доступны научные поля. Подтверждённые заимствования и формы требуют проверенных источников; простое добавление URL не снимает эту проверку. Прежние варианты, атрибуции и ссылки на страницы сохраняются.

Опубликуйте статью. На публичной странице появляются только её доступные языковые вкладки; скрытые и неготовые карточки не попадают в публичный API. Новые языки не включаются автоматически в основное исследование восьми слов. Для подробной статьи выберите «Подробная статья» или «Добавить подробное описание». Переключение обратно в компактный формат сохраняет научные поля в базе.

Кнопки «Сохранить черновик», «Предпросмотр» и «Опубликовать» разделены. Черновик уже опубликованного слова не заменяет публичный снимок. При уходе с несохранёнными изменениями выводится предупреждение. Автосохранения с автоматической публикацией нет.

## Новое «Слово дня»

«Создать статью» открывает заголовок, необязательное описание и визуальный редактор Tiptap. Можно писать и форматировать непосредственно в документе: заголовки, выделения, подчёркивание, зачёркивание, списки, цитаты, разделители, ссылки, изображения из медиатеки, таблицы, выравнивание, отмена и повтор. Для публикации нужны только заголовок и непустой текст. Изображение сначала загрузите в медиатеку с alt и подписью, затем выберите в редакторе. Вставка Word/Pages проходит через схему поддерживаемых элементов: внешние стили и неподдерживаемые блоки не сохраняются. Проверьте результат сложной вставки в предпросмотре.

Содержимое хранится как проверяемый JSON документа, не произвольный HTML. Ссылки и изображения проверяются сервером, публичный рендерер создаёт разрешённые React-элементы. Не разрешены JavaScript-URL, raw HTML, внешние изображения и произвольные типы блоков.

Прежние материалы остаются в Markdown и продолжают безопасно отображаться. В редакторе такого выпуска есть отдельное действие преобразования: текст переносится в визуальный документ абзацами, а исходные Markdown-поля остаются в записи. Прежнюю Markdown-разметку после такого преобразования можно вручную оформить панелью; оно не обещает идеального восстановления сложных таблиц или сносок. Автоматического разрушительного преобразования нет.

«Создать карточку слова» позволяет выбрать словарную статью либо создать новую прямо здесь — с теми же темами, ссылками и языками. Сначала «Сохранить слово и использовать» сохраняет его **черновик**. Для публикации выпуска нужно явно опубликовать связанное слово отдельной кнопкой или выбрать уже опубликованное. Выпуск не раскрывает черновой текст. Собственный заголовок и комментарий необязательны; заголовок по умолчанию берётся из опубликованного слова.

Выпуск хранит только связь со словарём: новые опубликованные языки появляются в нём автоматически, а дата выпуска остаётся прежней. Если слово снять с публикации, выпуск сообщает о недоступности, не подставляя скрытую версию. Удаление выпуска не удаляет слово.

Дата первой публикации нового материала устанавливается сервером автоматически в часовом поясе проекта. По умолчанию это Asia/Novosibirsk. Можно публиковать несколько материалов в день. Обычное редактирование дату не меняет. Планирование спрятано в дополнительных настройках; для будущего выпуска дата соответствует моменту доступности по расписанию. Старая календарная дата прежнего опубликованного выпуска сохраняется при редактировании/преобразовании. В публичной ленте — последние статьи и карточки; архив и прежние постоянные URL сохранены. Маршрут по дате может показывать несколько материалов за этот день.

## Очистка старых выпусков — только вашим действием

**На вашем Mac старые выпуски ещё не удалены. Миграция их не очищает.**

1. В «Слове дня» раскройте «Управление прежними выпусками».
2. Нажмите «Удалить все публикации „Слова дня“». Проверьте точное количество всех статусов и корзины.
3. Скачайте резервную копию кнопкой «Скачать резервную копию перед очисткой» и сохраните её у себя. Копия содержит владельца, сессии и черновики — не публикуйте её.
4. Нажмите «Переместить все выпуски в корзину» и введите **В КОРЗИНУ**. Словарь, исследование, журнал, источники и изображения не удаляются.
5. При необходимости восстановите выпуск через общую корзину — он вернётся черновиком.
6. Для необратимого удаления только выпусков из корзины требуется отдельная кнопка и фраза **УДАЛИТЬ НАВСЕГДА**. Если состав изменился, сервер откажет и потребует обновить счётчик.

Пустой раздел показывает «Новые публикации скоро появятся». Старые или фиктивные материалы при перезапуске не создаются.

## Откат

Остановите API и Vite. Сохраните текущее состояние в отдельную копию, чтобы не потерять новые правки. Переключитесь в GitHub Desktop на **feat/cms-stage2**, предварительно сохранив изменения кода. Восстановите копию **до** третьего этапа в новый файл:

```sh
test ! -e .cms/rollback-stage2.sqlite && cp "$HOME/russkiy-sled-backups/before-stage3.sqlite" .cms/rollback-stage2.sqlite
chmod 600 .cms/rollback-stage2.sqlite
CMS_DB_PATH="$PWD/.cms/rollback-stage2.sqlite" node --input-type=module -e 'import {DatabaseSync} from "node:sqlite"; const db=new DatabaseSync(process.env.CMS_DB_PATH); if(db.prepare("PRAGMA integrity_check").get().integrity_check!=="ok") throw new Error("База повреждена"); db.exec("DELETE FROM sessions; DELETE FROM attempts"); db.close(); console.log("ok");'
npm ci
npm run build
export CMS_DB_PATH="$PWD/.cms/rollback-stage2.sqlite"
npm run server
```

Если новый файл уже существует, используйте другое имя, не перезаписывайте его. Можно взять автоматическую копию before-stage3 из `.cms/backups/`. Исходную базу третьего этапа не удаляйте. Во втором окне запустите Vite обычной командой. Войдите прежним паролем. При следующих запусках API и резервировании задавайте тот же CMS_DB_PATH: без него откроется прежний `.cms/content.sqlite`. Старый код не предназначен для работы с новыми форматами на базе третьего этапа: откатывайте код **и** выбирайте копию до миграции.
