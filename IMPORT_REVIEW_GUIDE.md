# Согласованное обновление 21 существующей статьи и добавление 7 слов

Ветка: `feat/homepage-editorial-redesign`, продолжение `b7ff15a`. Обычная защита импорта сохранена. Новый режим не является `force`: он требует предварительного сравнения, действующего плана для конкретной базы и явного согласия с его полным кодом.

Во вложении к запросу оказался сам финальный JSON, побайтно совпадающий с файлом в репозитории (SHA-256 `ac4c5e719dc345dd78ffbb7e419bc62a7732685fda9baa2b21301d908cc3dc95`), а не отдельный локальный отчёт. Сценарий `create=7, replaceSeed=0, skip=0, conflicts=21` воспроизведён на отдельной тестовой SQLite. Доступа к базе MacBook нет; её обновление выполняет владелец командами ниже. Облачная пользовательская база в этой задаче не изменялась.

## Что сохраняется и что заменяется

Сохраняются ID, slug, обложка (`coverId`), связи с другими словами (`relatedWordIds`), вся прежняя история и публичные снимки. Ссылки журнала и «Слова дня» продолжают работать по прежним ID; строки этих разделов, их изображения и публикации не редактируются. Таблицы владельца, сессий, настроек и медиа не изменяются.

В существующий черновик переносятся содержательные поля финального набора: определение, ударение, часть речи, формат, этимологические сведения, тематические категории, научные примечания и выводы, языковые карточки и доказательные источники. Старые содержательные поля, которых нет в новом наборе, удаляются из **нового черновика** — это также видно в сравнении. Например, прежние библиографические `links` заменяются источниками финального набора; их записи в справочнике не удаляются. Полная прежняя статья сохраняется в истории. В существующих языках сохраняются редакторские переключатели `hidden`, `unpublished`, `expanded`. Остальные данные карточек заменяются по финальному JSON; дополнительные прежние карточки тоже показаны как удаление в черновике.

Результат всегда `state=draft`. Не присваиваются научные `verified`/`confirmed`, не устанавливаются даты проверки источников. Основная выборка остаётся 8 слов × `en-US`, `fr-FR`, `hy-AM`. Публичные версии остаются прежними до отдельной публикации владельцем. Согласие на обновление черновиков не является согласием на публикацию.

## Точные команды на MacBook

Все команды выполняйте в корне репозитория, в одном окне Terminal. Сохраните свои изменения кода; в GitHub Desktop нажмите **Fetch origin**, выберите `feat/homepage-editorial-redesign`, нажмите **Pull origin**. Остановите API и Vite сочетанием Control+C. Оставьте их остановленными до завершения импорта. Если база используется через `CMS_DB_PATH`, задайте тот же путь перед всеми командами; не переключайтесь на другую SQLite.

```sh
npm ci
npm run build
```

Ранее сделанную резервную копию сохраните. Перед применением новый режим автоматически создаст ещё одну консистентную копию SQLite, включая данные WAL, в каталоге `backups` рядом с используемой базой. При невозможности создать копию запись не начинается. Схема SQLite не меняется.

1. Создайте уникальное имя плана и предварительный просмотр:

   ```sh
   REVIEW_PLAN="$HOME/Desktop/russkiy-sled-review-$(date +%Y%m%d-%H%M%S).json"
   npm run content:import -- --review "$REVIEW_PLAN"
   ```

   Эта команда открывает существующую базу только для чтения. Рядом с JSON создаётся файл с окончанием `.json.html`; оба имеют права 0600. Существующие файлы не перезаписываются. В вашем сценарии ожидается `create: 7`, `updateReviewed: 21`, `blocked: 0`. Числа рассчитываются по вашей базе, а не подставляются.

2. Откройте сравнение в Safari:

   ```sh
   open -a Safari "${REVIEW_PLAN}.html"
   ```

   Раскройте нужные слова и прочитайте столбцы **«Поле / Было / Станет»**. Языковые карточки сопоставляются по коду языка. Добавления и удаления показаны отдельно; весь список из 28 слов доступен в одном файле. Проверьте сохранённые ID, URL и изображения. Этот HTML ничего не применяет, не загружает внешних ресурсов и не содержит скриптов. Храните его и JSON локально: в них есть ваши редакторские тексты; не добавляйте их в Git.

3. Только если вы согласны заменить показанные содержательные поля, запустите применение:

   ```sh
   npm run content:import -- --apply-review "$REVIEW_PLAN" --report "${REVIEW_PLAN%.json}-result.json"
   ```

   Терминал попросит ввести **полный 64-символьный код плана**, указанный в HTML и выводе команды. Вставьте код и нажмите Enter. Пустой ввод или неверный код отменяет операцию до записи и создания резервной копии. Это явное согласие владельца на весь показанный пакет, включая 21 обновление и 7 добавлений. Чтобы сохранить отдельные прежние поля, отмените операцию: выборочного слияния в этом режиме нет.

   Для неинтерактивного терминала предусмотрена только явная форма `--apply-review ПУТЬ --confirm ПОЛНЫЙ_КОД`, где код владелец берёт из уже просмотренного плана. Не используйте автоматическое извлечение кода вместо просмотра.

4. Проверьте результат. Ожидается `imported: 28`, `updateReviewed: 21`, `create: 7`, `conflicts: []`. В отчёте есть `mapping` с исходными и сохранёнными ID/URL, `reviewId` и путь к резервной копии. Общее число записей всей базы может быть больше 28: остальные слова не удаляются.

   Если после просмотра вы редактировали базу, добавили слово, изменили категории, источники или связанные материалы, команда отклонит устаревший план без записи. Снова выполните шаги 1–3 с новым именем и заново просмотрите изменения. Не исправляйте `stateHash`, `id` и содержимое JSON вручную. Если передумали, просто не запускайте применение.

5. Запустите API:

   ```sh
   npm run server
   ```

   Во втором терминале, в корне проекта:

   ```sh
   npm run dev -- --port 5173 --strictPort
   ```

6. В Safari откройте `http://localhost:5173/admin` и войдите прежним паролем. В CMS выберите «Черновик», проверьте 28 слов по `mapping`: определения, языки, этимологию, источники и выводы. Проверьте сохранение пользовательских изображений. Отредактируйте одну запись, сохраните и перезагрузите страницу. Публичный сайт `http://localhost:5173/` должен показывать прежние опубликованные снимки; новые слова до публикации отсутствуют.

Если открыли другое окно Terminal, переменная `REVIEW_PLAN` там не задана: используйте полный путь к уже созданному JSON, указанный в выводе команды. Если финальный JSON берёте из другого каталога, передайте одинаковый `--file "/полный/путь/russkiy-sled-content-final.json"` и при просмотре, и при применении; по умолчанию берётся правильный файл из репозитория.

## Защита и ограничения

- Неверный код, изменённый JSON-план, другой файл данных, другая база или устаревшее состояние останавливают запись. Проверка актуальности выполняется заново под блокировкой записи SQLite, в той же транзакции, что и весь импорт.
- Неоднозначное сопоставление слов, изменённые источники `final-*`, несовпадающая страна языка, архивные/удалённые записи и изменённый ранее импортированный пакет остаются блокирующими конфликтами. Этот режим разрешает только рассмотренную замену содержательных полей существующих активных статей; глобальная защита не отключена.
- Повтор успешно применённого плана возвращает `imported: 0`, `skip: 28` и сохраняет более поздние правки владельца. Новый план для уже импортированного пакета также пропускает эти записи. Повтор может создать дополнительную резервную копию, но не создаёт дубликатов статей или версий.
- При любой ошибке во время записи откатываются все 28 слов, новые источники, категории, языки и журнал импорта. Исходная база не подменяется облачной копией. При сообщении об ошибке после создания резервной копии её путь уже напечатан в терминале.
- Старые пользовательские источники не удаляются и не перезаписываются. Конфликты справочников нельзя подтвердить этим кодом: потребуется отдельное ручное согласование.
- Для научной проверки остаются прежние ограничения из `CONTENT_IMPORT_GUIDE.md` и `research/imports/IMPORT_TEST_REPORT.json`: источники, тип соответствия, происхождение, неподтверждённая IPA и армянские спорные формы. Ничто не публикуется массово автоматически. Публикация — отдельное действие владельца в CMS после проверки.
