# «Русский след» — техническое задание на цифровой лингвистический ресурс

**Версия:** 1.0 · **Дата:** 03.11.2026 · **Назначение:** техническая спецификация для OpenAI Codex в VS Code.

## 0. Контекст и приоритеты

«Русский след» — самостоятельный русскоязычный научно-образовательный веб-ресурс о словах, пришедших **из русского языка** в другие языки, в том числе через языки-посредники. Это не проект об иностранных заимствованиях в русском. Первая исследовательская тройка: **американский английский (США), французский (Франция), восточноармянский (Армения)**. Проект также является практическим результатом школьной НПК; важна возможность показать локальную рабочую версию **5 ноября 2026 года**. После НПК ресурс продолжит развиваться.

**Высший приоритет:** качественный рабочий словарь с поиском, страницами слов, источниками и научной прозрачностью. **Не жертвовать научной достоверностью ради заполненности интерфейса.** Анкетирование в текущий объём сайта не входит, его результаты нельзя выдумывать.

Нужно построить настоящую поддерживаемую кодовую базу, а не один гигантский HTML-файл и не статическую картинку. Старый проект не использовать.

## 1. Технологический подход

- React + TypeScript, Vite, Tailwind CSS (совместимые актуальные версии), React Router, Lucide icons.
- Локальные типизированные JSON/TypeScript-данные для первой версии; отдельный слой чтения/валидации данных, чтобы позже добавить Supabase без переделки интерфейса.
- Fuse.js или эквивалентный поддерживаемый механизм клиентского нечёткого поиска. Не подключать внешнюю ИИ-модель к поиску.
- Компонентная архитектура, мобильная адаптация, семантическая разметка, понятная навигация.
- Никаких платных сервисов, ключей API, авторизации или отдельного backend на первом этапе.
- Не публиковать сайт и не создавать публичный репозиторий без подтверждения владельца.
- Оформить README.md с установкой, запуском, сборкой и правилами добавления слов.

Если проект уже существует, сначала изучить файлы и бережно продолжить; ничего не перезаписывать без нужды.

## 2. Дизайн и визуальный язык

Ощущение: **престижное научное издательство / цифровая лексикографическая библиотека**. Не шаблонный SaaS-дашборд, не игровая энциклопедия, без неоновых градиентов, без тяжёлых декоративных эффектов.

- Основной фон: тёплый молочный `#F6F3EB` (допускаются близкие оттенки), карточки светлее.
- Текст: графит `#252930`; основной акцент: глубокий тёмно-синий `#203A60`.
- Вторичные границы: `#E2DED6`; умеренные мягкие тени и тонкие разделители.
- Логотип типографический: **Русский след.** Не использовать несуществующие брендовые файлы.
- Титульные заголовки с умеренной редакционной засечкой (системный Georgia как безопасный fallback); основной текст — качественный sans-serif.
- Desktop: постоянная левая вертикальная навигация; мобильная версия: адаптивное сворачиваемое меню.
- Много свободного пространства, ровная сетка, выразительная иерархия заголовков, аккуратные микроанимации, хороший контраст.
- Основной интерфейс полностью **на русском**; иностранные формы слов — в оригинальной графике.
- Уважать `prefers-reduced-motion`; клавиатурная навигация и видимый focus.

## 3. Разделы и маршруты

1. `/` **Главная** — крупный центральный поиск, рядом или справа редакционная колонка журнала; блоки «Слово дня», «Карта русского следа», «Путешествие слова», короткий рассказ о проекте; по возможности интерактивный предварительный поиск.
2. `/dictionary` **Словарь — основной продукт** — список слов, поиск, подсказки, фильтры по языку и тематике, сортировка, удобные состояния отсутствия результатов.
3. `/dictionary/:slug` **Словарная статья** — русское исходное слово, этимологическая справка, темы, сведения об источниках; карточки иностранных языков на одной странице с **независимым** раскрытием; возможность фильтра языка внутри длинной статьи; статусы и дата проверки.
4. `/research` **Сравнительное исследование** — объяснение методики и интерфейс сравнения зафиксированных форм (США/Франция/Армения). Выделить графику, фонетику, семантику, грамматику и степень освоенности. Не требовать, чтобы каждое слово существовало во всех трёх языках. Для недостающих данных — честный статус.
5. `/map` **Карта русского следа** — интерактивная карта с выбором страны; при выборе справа появляется боковая панель с **подтверждёнными** словами по всем языкам страны и дальнейшим фильтром по языку; плавное открытие. На первой версии достаточно честно реализовать страны исследования, не придумывать данные для мира.
6. `/journey` и `/journey/:slug` **Путешествие слова** — понятная история распространения конкретного слова без чрезмерно сложной временной шкалы; даты и маршруты показывать только при наличии источников.
7. `/journal` и `/journal/:slug` **Журнал** — лента публикаций и самостоятельные статьи; категории/теги необязательны, публикации научно проверяются.
8. `/word-of-the-day` **Слово дня** — из опубликованных подтверждённых статей; детерминированный выбор на сутки, без выдуманных новинок; если проверенных данных нет — корректная заглушка.
9. `/contribute` **Предложить слово** — понятная форма без обязательной регистрации; email необязателен. На первой статической версии можно только показать форму и явно обозначить «Приём предложений пока не подключён» **без фальшивой отправки**. На будущем этапе — база, валидация, антиспам и модерация.
10. `/report-error` **Сообщить об ошибке** — отдельная форма/канал, не смешивать с предложением слова; до появления backend не имитировать успешную отправку.
11. Понятная страница 404; навигация и ссылки должны работать.

## 4. Три уровня наполнения словаря

**А. Краткая статья** — большая часть словаря. Минимально: русская лемма, иностранная форма (если подтверждена), принимающий язык, краткое значение, тип происхождения, ссылка на источник, статус проверки. Подробный фонетико-грамматический анализ не обязателен.

**Б. Развёрнутая научная статья** — примерно **10–15 показательных исходных слов**, по мере исследования: форма каждого засвидетельствованного языка, графические, фонетические, семантические, грамматические изменения, степень освоения, примеры, библиография, вывод. Эти слова представляют разные тематические группы и механизмы адаптации; отдельный пример не доказывает закономерность для всей группы.

**В. Статья в разработке** — сведения частично собраны: видимое обозначение **«Материал собирается»** рядом с конкретным неполным полем/языком; подтверждённая часть показывается, неподтверждённая не додумывается.

**Нельзя смешивать полноту статьи и её достоверность:** краткая статья может быть подтверждённой, подробная может содержать открытые вопросы.

## 5. Достоверность и научная методика

- Русский язык — источник или посредник; остальные — языки-реципиенты.
- Различать `исконно русское`, `через русский`, `спорное`, `не установлено`.
- Подтверждение иностранной формы: авторитетный словарь + этимологические сведения по возможности; корпус и научные статьи для дополнительных наблюдений.
- Ссылки должны быть реальными. Не сочинять библиографию, цитаты, IPA, грамматические формы, примерные даты, частотность, этимологии, распространённость.
- При отсутствии доказательства не публиковать утверждение как факт. Показывать «Не установлено», «Исследование продолжается» или «Материал собирается» по смыслу.
- Публичная карточка показывает: источник(и), статус, основание статуса, дату последней проверки, где применимо — альтернативную научную версию с атрибуцией.
- Никаких вымышленных респондентов или результатов анкет. Не превращать макет в псевдоисследование.
- Не использовать для академического обоснования литературу **о проникновении иностранных слов в русский**; для теории нужны общие работы о контактах и статьи о русизмах **в иностранных языках**.
- Тематическая классификация и виды адаптации — **две отдельные оси анализа**.
- Подсчёты выводить только по записям с нужным подтверждённым статусом. Показывать количество именно подтверждённых слов, а не всех кандидатов.

## 6. Модель данных (строго типизировать)

Создать TypeScript-типы/схемы в `src/domain/` и демо-данные в `src/data/`.

Минимальные сущности:

**WordEntry**:
- `id`, `slug`, `russianLemma`, `russianStress?`, `shortDescription?`;
- `originKind: 'native-russian'|'via-russian'|'disputed'|'unknown'`;
- `originNotes?`, `themes: string[]`;
- `articleDepth: 'short'|'full'`;
- `publicationStatus: 'verified'|'provisional'|'draft'`;
- `languages: BorrowedForm[]`;
- `sourceIds: string[]`, `checkedAt?`, `editorialNotes?`, `researchIncluded: boolean`;
- `isDemo?: boolean` (демо-данные должны быть явно исключены из реальной статистики).

**BorrowedForm**:
- `languageCode` (первый набор: `en-US`, `fr-FR`, `hy-AM`), `countryCode`, `spelling?`, `alternativeSpellings?`, `ipa?`, `meaning?`;
- `partOfSpeech?`, `grammaticalGender?`, `pluralForms?`, `inflection?`, `register?`;
- `attestationStatus: 'verified'|'pending'|'disputed'|'unknown'`;
- `adaptation: {graphic?, phonetic?, semantic?, grammatical?, integration?}`; у каждого наблюдения есть текст, источник(и), статус;
- `examples?` (только с точной атрибуцией), `firstAttested?` (только с подтверждением), `sourceIds`, `checkedAt?`.

**SourceRecord**:
- `id`, `authors?`, `title`, `year?`, `publisherOrJournal?`, `url?`, `doi?`, `pages?`, `accessLevel: 'full'|'section'|'abstract'|'bibliography'`, `verifiedAt?`, `notes?`.

Добавить валидацию схем (например Zod либо типизированные валидаторы) и скрипт/тест для недействительных перекрёстных `sourceIds`. Подтверждённая форма без источника должна вызывать ошибку проверки данных или как минимум блокировать вывод как «Подтверждено».

Первоначальное содержимое: **не генерировать 50 якобы проверенных слов**. Если реальные данные не переданы, показать явные демонстрационные записи, помеченные «Демонстрация интерфейса», либо пустые состояния. Демозаписи не учитывать в статистике и не обозначать как академически проверенные. Подготовить функцию импорта CSV/JSON в будущем.

## 7. Поиск и фильтры

- Искать по русской кириллице, латинским формам, альтернативным написаниям, текстовым темам; запрос `бабушка` должен находить ту же карточку, где засвидетельствована иностранная `babushka`, и наоборот (если запись существует).
- Нормализация регистра, `ё/е`, пробелов и распространённых разделителей; нечёткий поиск по опечаткам; автоподсказки.
- Фильтры: язык, тематическая группа, уровень статьи, статус, участие в сравнительном исследовании; сортировка по алфавиту и другим обоснованным полям.
- При выборе нескольких языков два режима: **«хотя бы в одном выбранном»** и **«во всех выбранных»**. Для режима «во всех» учитываются только *подтверждённые* формы.
- Не считать отсутствие записи доказательством отсутствия заимствования в языке.
- Учитывать производительность для 200+ записей; доступный поиск с клавиатуры.

## 8. Карта, журнал и формы — правила поведения

- Карта рисуется из существующих данных; страна без подтверждённых записей — «Пока нет подтверждённых слов». Не выводить фиктивные показатели на карте.
- Боковая панель карты открывается при выборе, закрывается пользователем, имеет фильтр по языку, не ломает мобильную версию.
- «Путешествие слова»: если маршрут неизвестен, показывать только доказанные этапы; не заполнять историю придуманными датами.
- Журнал использует отдельный набор редакционных публикаций; статус `draft` не виден как опубликованная статья.
- Слово дня строится из подтверждённых записей и не выбирает `isDemo`.
- Публичные формы в статическом MVP не должны вводить посетителя в заблуждение о сохранении сообщения. Для последующего подключения предусмотреть серверное хранение, защиту от спама, модерацию и безопасную обработку необязательного email.

## 9. Порядок реализации (стоп после каждого этапа с отчётом)

**Этап 1 — проверяемый MVP к 05.11.2026**:
1. Scaffold React/Vite/TS/Tailwind/Router.
2. Общая оболочка, дизайн-система, левое меню, мобильная версия, страницы и 404.
3. Главная с работающим поисковым переходом и корректными блоками.
4. Словарь с локальными типизированными данными, полнофункциональными фильтрами и поиском.
5. Статья слова с отдельными раскрывающимися карточками языков, статусами, источниками, датой проверки.
6. Страница сравнительного анализа — работающий анализ имеющихся записей, честные пустые состояния.
7. `npm run build`, проверка линтера/типов, базовые тесты поиска/фильтров и README.
8. Зафиксировать, что уже работает, а что ещё прототипируется. Ничего не выдавать за завершённое без проверки.

**Этап 2 — после стабильного MVP:** карта со странами исследования и правой панелью, страницы журнала и истории слова, слово дня, расширение контента.

**Этап 3 — после первой демонстрации:** серверные формы предложений и сообщений об ошибке, редакционная модерация, Supabase (по согласованию), затем публикация на Vercel и домен.

Поддерживать ясный список задач в `PLAN.md` со статусами (`готово / выполняется / планируется`). Не пытаться сделать все этапы за один запрос. После каждого этапа показывать точные изменённые файлы, команды проверки, оставшиеся ограничения и следующий шаг.

## 10. Приёмочные критерии

- `npm install` и `npm run dev` работают на MacBook.
- `npm run build` проходит без ошибок; проект не требует API-ключей для демо.
- Основные ссылки/маршруты рабочие; ошибки маршрутизации корректно обработаны.
- Главная и словарь удобны и на широком экране, и на смартфоне.
- Поиск по русской лемме и иностранной форме, режимы `любой/все языки`, фильтры и пустые состояния работают.
- Статусы не смешаны, непроверенные сведения не помечены подтверждёнными.
- Карточки поддерживают одновременно краткий и подробный режим, а также отдельные недостающие поля.
- Данные вынесены из JSX, хорошо типизированы; источники имеют кликабельные ссылки.
- Визуальное оформление выдержано в редакционном стиле: тёплый фон, графит, тёмно-синий, типографический логотип.
- README позволяет другому разработчику запустить проект и добавить новую словарную запись.
- Публичный деплой/формы не имитируются; незавершённые функции помечены честно.

## 11. Как работать с владельцем проекта

- Владелец не обязан программировать. Пиши отчёты на русском простым языком.
- Если задачу можно обоснованно решить самому, делай это, не заваливая владельца вопросами.
- Не разрушать стабильные части ради новых функций; перед крупными изменениями проверять приложение и сохранять возможность отката через Git.
- При нехватке времени предпочитать работающую демонстрацию словаря, а не множество красивых неработающих экранов.
- Не отправлять изменения в публичный GitHub, не разворачивать серверную инфраструктуру и не запускать платные сервисы без явного разрешения.
