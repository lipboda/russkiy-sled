# Запуск «Русского следа» на MacBook перед защитой

Нужны GitHub Desktop, Safari, Терминал и Node.js. Серверная архитектура не менялась: React/Vite + Node.js API + SQLite. Внешняя база, Docker, API-ключи и платные сервисы не нужны. Второй этап CMS не включён.

## 1. Получить готовую версию через GitHub Desktop

Репозиторий: https://github.com/lipboda/russkiy-sled
Ветка передачи: **release/cms-stage1-macbook**.

Если репозиторий уже есть на Mac:

1. В GitHub Desktop выберите `russkiy-sled` в Current Repository.
2. Если слева в Changes есть ваши изменения, сначала сохраните их отдельным коммитом. Не используйте Discard Changes и не удаляйте файлы ради переключения.
3. Нажмите **Fetch origin**.
4. Откройте **Current Branch** и найдите `release/cms-stage1-macbook`. Выберите эту ветку. Если появится Pull origin — нажмите его.
5. В History должен появиться коммит `Complete CMS stage one and prepare MacBook demonstration`.

Если репозитория ещё нет: **File → Clone Repository → URL**, вставьте адрес репозитория выше, выберите папку, нажмите Clone. Затем выберите ветку передачи через Current Branch.

После переключения откройте папку проекта: **Repository → Show in Finder**. Файл, который вы читаете, должен присутствовать. Для команд выберите **Repository → Open in Terminal**; если пункта нет, откройте Терминал и введите `cd ` с пробелом, перетащите папку проекта из Finder и нажмите Enter. Все команды ниже выполняются из корня `russkiy-sled`, где лежит package.json. Не запускайте их внутри server или src.

## 2. Установить Node.js один раз

Проверенная комбинация: **Node.js 24.22.1, npm 11.9.0**. Используйте ветку Node.js **24.x, не ниже 24.22.0**: она нужна для встроенного SQLite и запуска TypeScript-схем сервером. npm устанавливается вместе с Node.js; отдельно обновлять его перед защитой не нужно. Точный проверенный Node указан в `.nvmrc`.

Если Node ещё нет: откройте https://nodejs.org/en/download, выберите официальный установщик macOS для Node.js 24.x с версией не ниже указанной, установите его. Затем закройте и заново откройте Терминал.

Проверьте:

```sh
node --version
npm --version
```

Если вы уже пользуетесь nvm, в корне проекта достаточно `nvm install`, затем `nvm use`: будет использована `.nvmrc`. Устанавливать nvm специально не требуется.

## 3. Установить зависимости и проверить сборку

Интернет нужен для скачивания зависимостей; сделайте это до защиты:

```sh
npm ci
npm run build
```

Дождитесь завершения без ошибок. Не заменяйте npm ci на обновление пакетов. Предупреждения сборщика о размере JS-файла и аннотациях Zod не означают падение сборки.

## 4. Создать личного владельца на Mac

В том же терминале:

```sh
bash scripts/create-owner.sh
```

Команда создаст SQLite с 58 исходными записями, если базы ещё нет. Затем попросит новый пароль дважды. Ввод скрыт: ни букв, ни звёздочек не будет — это нормально. Длина пароля — от 14 до 256 символов. Сохраните его в менеджере паролей. Email и отдельный логин не нужны. Дождитесь «Владелец создан».

Это ваша **локальная** учётная запись на Mac; она не зависит от облачной машины. Пароля по умолчанию нет. Повторный запуск не заменяет существующего владельца и его пароль. Команда не сохраняет пароль в Git или .env, а в базе хранится только scrypt-хеш. Пароль не присылайте в чат.

## 5. Запустить API — первое окно Терминала

```sh
npm run server
```

Оставьте окно открытым. Ожидаемое сообщение: «CMS: сервер слушает loopback, порт 3001». Если владелец ещё не создавался, первый запуск API сам создаст базу и наполнит её 58 записями. Повторный запуск сохраняет существующие данные, не заменяет ваши правки исходным каталогом.

## 6. Запустить frontend — второе окно Терминала

Снова откройте терминал в той же папке проекта через GitHub Desktop или Finder и выполните:

```sh
npm run dev -- --port 5173 --strictPort
```

Оба окна должны оставаться открытыми. Для остановки нажмите Control+C в каждом. При следующем запуске достаточно двух команд из шагов 5 и 6; устанавливать зависимости и создавать владельца заново не нужно.

В стандартном локальном запуске **не нужны переменные окружения или .env**. CMS_ORIGIN по умолчанию равен `http://localhost:5173`, API-порт — 3001. Если вы ранее сами задавали CMS_DB_PATH, PORT, CMS_ORIGIN или NODE_ENV, проверьте, что они не изменяют этот стандартный запуск.

## 7. Открыть сайт в Safari

Введите в адресную строку Safari на вашем Mac:

- Сайт: **http://localhost:5173/**
- Административная панель: **http://localhost:5173/admin**
- Демонстрационная статья: **http://localhost:5173/dictionary/matryoshka**
- Исследование: **http://localhost:5173/research**

Используйте именно `localhost`, а не `127.0.0.1`: origin интерфейса должен совпадать с настройкой API для входа и сохранения. Не используйте команду preview для основной демонстрации CMS; здесь нужен Vite с API-прокси, как в шаге 6. Не открывайте dist/index.html двойным щелчком.

В `/admin` введите ваш пароль и нажмите «Войти». Должны появиться «Редакция словаря», обзор, 58 записей и кнопка «Выйти». Перезагрузите страницу — вход сохранится в обычном окне Safari, пока не истекла 8-часовая сессия. После истечения просто войдите снова.

## 8. Репетиция перед защитой

1. Найдите в словаре «Матрёшка», откройте статью и три языковые карточки.
2. Перейдите в сравнение. Покажите одно слово и таблицу основного набора из восьми слов.
3. После входа в CMS откройте статью → «Редактировать статью».
4. Запомните исходное редакционное примечание. Добавьте «Проверка CMS перед защитой» только в это поле, не меняя научные факты.
5. Выберите редакционный статус «Опубликовано» внизу формы. Научные статусы не меняйте.
6. Сохраните, подтвердите публикацию, дождитесь «Версия сохранена. Опубликовано».
7. Откройте статью, обновите страницу Safari: примечание должно остаться.
8. Откройте ту же статью в **File → New Private Window**: изменение видно, административной панели нет.
9. В обычном окне верните исходное примечание и снова опубликуйте.
10. Проверьте поиск `samovar`, отображение армянских форм и ширину сравнительной таблицы на вашем экране.
11. Выйдите и войдите повторно, чтобы убедиться, что пароль сохранён у вас правильно.

Проверки облачной Linux-машины не заменяют эту репетицию в Safari. Реальный Safari в текущей среде не запускался.

## 9. База и резервная копия

Внутри вашей папки проекта база находится по пути **`.cms/content.sqlite`**. Точка в начале делает папку скрытой в Finder; для отображения скрытых файлов нажмите **Command+Shift+.**

**Отдельный файл базы для первого переноса не нужен.** Все 58 исходных записей, включая Unicode, армянские формы, источники и статусы, уже содержатся в `src/data/catalog.json` и переходят через GitHub. Первый запуск создаёт SQLite из этого файла. Личная облачная база и учётная запись не передаются.

Редактирование в CMS меняет SQLite на вашем Mac, а не JSON в Git. Поэтому Pull origin не переносит CMS-правки между компьютерами. Не удаляйте `.cms/` при обновлении кода. Папка `.cms/` и файлы SQLite исключены из Git.

После создания владельца и репетиции сделайте резервную копию:

```sh
mkdir -p -m 700 "$HOME/russkiy-sled-backups"
npm run db:backup -- "$HOME/russkiy-sled-backups/before-defense.sqlite"
```

Сервер может работать: команда делает согласованную копию SQLite с учётом WAL. Для следующей копии используйте другое имя, например `after-defense.sqlite`: существующая копия не перезаписывается. Не заменяйте эту команду обычным cp работающей базы.

Сохраните копию также на другом носителе. Она содержит черновики, хеш пароля и сессии — не публикуйте её в GitHub. Если позже понадобится перенести уже отредактированную базу между компьютерами, используйте резервную копию, остановите целевой API, восстановите её в новый файл и отзовите старые сессии по процедуре ADMIN_GUIDE.md. Для текущего первого запуска это не требуется.

## 10. Если что-то не запускается

- `node: command not found` или `npm: command not found`: установите Node, переоткройте Терминал.
- Ошибка `node:sqlite` или TypeScript-схемы: проверьте `node --version`; нужна Node 24.22+ ветки 24, затем выполните npm ci заново.
- `package.json` не найден: терминал открыт не в корне проекта. Вернитесь в папку через GitHub Desktop.
- `EADDRINUSE` / порт занят: проверьте, не запущено ли уже приложение в другом окне. Остановите только свою старую копию Control+C. Не выбирайте случайный другой порт: это изменит настройки origin/proxy.
- Главная открывается, но данные или вход не работают: проверьте первое окно с API. Оба процесса должны работать.
- «Недопустимый источник запроса»: используйте адрес `http://localhost:5173`, не другой хост/порт.
- «Владелец не настроен»: выполните `bash scripts/create-owner.sh` в той же папке проекта, где запущен API.
- «Владелец уже создан»: это защита существующего пароля; второй владелец не требуется. Не удаляйте базу для повторного создания.
- Слишком много попыток входа: подождите 15 минут и используйте правильный пароль.
- Изменение не видно посетителям: нужен редакционный статус «Опубликовано» и успешное подтверждение сохранения. Черновик не заменяет прежний опубликованный снимок.

Для демонстрации после npm ci внешний интернет не нужен для основных функций: приложение, каталог и SVG-карта локальные. Переходы к внешним научным источникам требуют интернета. Репозиторий и зависимости заранее сохраните на Mac; закройте режим сна, проверьте заряд и выполните репетицию до защиты. Публичный деплой не требуется.
