# Инструкции Codex для репозитория «Русский след»

1. Перед работой прочитай `PROJECT_SPEC.md`. Это источник требований и границ проекта.
2. Проект — про движение **из русского в иностранные языки**, а не наоборот. Основные: `en-US`, `fr-FR`, `hy-AM`.
3. Разрабатывай по этапам из `PROJECT_SPEC.md`, не пытайся реализовать всё сразу. Приоритет — рабочие главная, словарь, статья, поиск и сравнение.
4. Не выдумывай словарные данные, источники, датировки, переводы, IPA или статистику. Демоданные явно маркируй и исключай из реальных счётчиков.
5. Учитывай разделение `articleDepth`, `publicationStatus`, `attestationStatus` и статусов отдельных полей. Отсутствие данных не означает отсутствие слова в языке.
6. Данные и типы держи отдельно от компонентов. Используй доступную, отзывчивую русскоязычную UI-архитектуру.
7. После каждого изменения запусти доступные проверки (`npm run build`, типы/линтер/тесты). Если проверка невозможна, объясни почему.
8. Никогда не имитируй успешную отправку формы, публикацию или научную проверку. Не включай платные сервисы, публичный деплой, secrets или API без явного запроса.
9. Не перезаписывай существующие пользовательские файлы; сохраняй Git-историю и предлагай логичные коммиты.
10. По завершении каждого этапа кратко по-русски сообщай: что реально работает, как запустить, что проверено, что ещё не готово.
11. До импорта словарных данных прочитай `research/UPLOADED_DOSSIERS_MANIFEST.md` и все восемь исходных досье. Создай `research/IMPORT_AUDIT.md`; не подменяй чтение PDF краткими резюме или извлечённым TXT.
